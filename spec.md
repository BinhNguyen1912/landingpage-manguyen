# SPEC.md — Mẫnthợtóc Landing Page & Booking MVP

## 1. Overview

Build a mobile-first personal landing page for the hairstylist brand:

- Username: `nguyen.anh.man`
- Display name: `Mẫnthợtóc`

The website provides:
1. A personal landing page / profile.
2. Hairstyle and work gallery.
3. Social/contact buttons.
4. A simple hair appointment booking flow.
5. Persistent booking storage in PostgreSQL.

The MVP should be simple to operate, easy to maintain, and suitable for low traffic (<100 bookings/day).

## 5. Booking Form

### Fields

| Field | Type | Required | Description |
|---|---|---:|---|
| `name` | string | Yes | Customer's full name |
| `phone` | string | Yes | Customer's phone number (for appointment confirmation) |
| `bookingDate` | date | Yes | Date the customer wants a haircut |
| `bookingTime` | time | Yes | Time the customer wants a haircut |
| `note` | text | No | Customer's haircut request / additional note |
| `createdAt` | timestamp | System | Time the booking was created |

### Example

```json
{
  "name": "Nguyễn Văn A",
  "phone": "0901234567",
  "bookingDate": "2026-09-20",
  "bookingTime": "14:00",
  "note": "Muốn cắt layer, giữ phần mái dài"
}
```

`createdAt` must be generated by the system/database and should not be manually entered by the customer.

## 7. Booking Time Slots

Customers should select from predefined time slots instead of entering arbitrary times.

Example:

```text
09:00
09:30
10:00
10:30
11:00
11:30
14:00
14:30
15:00
15:30
16:00
16:30
17:00
17:30
```

Actual working hours / available slots can be configured later.

### UI

Available:

```text
+--------+  +--------+
| 09:00  |  | 09:30  |
+--------+  +--------+
```

Already booked:

```text
+--------+
| 14:00  |
| Đã đặt |
+--------+
```

Booked slots must not be selectable.

## 8. Booking Conflict / Double Booking

A date/time slot can only have one active booking.

The database must enforce uniqueness for:

```text
bookingDate + bookingTime
```

Recommended unique constraint:

```sql
UNIQUE (bookingDate, bookingTime)
```

The frontend availability check is only a UX optimization.

The database remains the source of truth.

If two customers attempt to book the same slot concurrently:

```text
Customer A -> SUCCESS
Customer B -> CONFLICT
```

Customer B receives:

```text
Khung giờ này vừa được người khác đặt.
Vui lòng chọn khung giờ khác.
```

## 9. Validation

### `name`

- Required.
- Must not be empty.

### `phone`

- Required.
- Must not be empty.
- Must be a valid Vietnamese phone number format (e.g. `09xxxxxxxx`, `03xxxxxxxx`, `07xxxxxxxx`).
- Apply a reasonable maximum length (`VARCHAR(20)`).

### `bookingDate`

- Required.
- Must be a valid date.
- Must not be in the past.

### `bookingTime`

- Required.
- Must be one of the configured booking slots.
- Must still be available at submission time.

### `note`

- Optional.
- Allow customers to describe hairstyle preferences or other requests.
- Apply a reasonable maximum length.

## 10. API

### Create booking

```http
POST /api/bookings
```

### Request

```json
{
  "name": "Nguyễn Văn A",
  "phone": "0901234567",
  "bookingDate": "2026-09-20",
  "bookingTime": "14:00",
  "note": "Muốn cắt layer"
}
```

### Server responsibilities

1. Validate request.
2. Validate date/time.
3. Verify the selected slot.
4. Create the booking.
5. Handle unique-constraint conflicts.
6. Return success/error response.

### Success response

```json
{
  "success": true,
  "bookingId": "uuid"
}
```

### Conflict response

```json
{
  "success": false,
  "code": "BOOKING_SLOT_UNAVAILABLE",
  "message": "Khung giờ này vừa được người khác đặt."
}
```

## 12. Performance / Smooth UX

The page should feel fast and smooth on mobile.

### Images

- Optimize large images before deployment.
- Prefer WebP/AVIF where practical.
- Do not load unnecessarily large source images.
- Above-the-fold avatar should load with high priority.
- Gallery images can use lazy loading.

### Layout stability

Reserve image dimensions/aspect ratios to prevent layout shifts.

### Animation

Use lightweight CSS transitions.

Prefer animating:

```text
transform
opacity
```

Avoid unnecessary layout-triggering animations.

### Scrolling

Use smooth scrolling for internal sections.

### Booking

The booking UI should open immediately; only database operations should require network requests.

Availability data can be fetched for the selected date and rendered locally.

---

## 13. Security

- Never expose Supabase `service_role` credentials in frontend code.
- Frontend must only use public/client credentials where appropriate.
- Protect database access with Supabase Row Level Security (RLS).
- Validate all booking input server-side/database-side.
- Do not trust frontend validation alone.
- Do not allow arbitrary database reads that expose other customers' personal information.

Customer data includes:

```text
name
age
booking information
note
```

and should not be publicly readable.
